Чтобы добавить поддержку MizLang в IDE, вам нужно создать **языковой сервер (LSP)** — отдельную программу, которая будет общаться с редакторами по стандартному протоколу. Это эффективнее, чем писать
плагин для каждой IDE.

Вот ключевые шаги, с акцентом на интеграцию с JetBrains:

### 🔧 Два пути поддержки языка

| Подход                       | Что это                                                       | Плюсы для MizLang                                                                                                                             | Минусы для MizLang                      |
|:-----------------------------|:--------------------------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------|
| **Language Server (LSP)**    | Отдельный сервер, общается со всеми редакторами по протоколу. | **Один раз** написать — получить поддержку в **VS Code, JetBrains, Vim** и др. Логичнее всего строить на вашей кодовой базе (лексер, парсер). | Требуется реализация всего протокола.   |
| **Нативный плагин для IDEA** | Глубокая интеграция в платформу JetBrains (PSI-дерево).       | Максимальная интеграция и производительность внутри IDE.                                                                                      | Работает **только** в средах JetBrains. |

Для нового языка, особенно если вы планируете поддержку в разных редакторах, **языковой сервер — предпочтительный путь**.

### 🧩 Архитектура вашего LSP-сервера

Сервер — это отдельная программа, которая использует ядро MizLang (парсер и семантический анализатор) и общается с IDE через **JSON-RPC**.

1. **Основной цикл**: Читает JSON-сообщения из `stdin`, парсит их, выполняет запросы и пишет ответы в `stdout`.
2. **Обязательные запросы**: Сервер должен отвечать хотя бы на `initialize` (предоставляет список поддерживаемых возможностей) и `shutdown`.
3. **Работа с документами**: Сервер хранит состояние открытых файлов, получая уведомления `textDocument/didOpen`, `didChange`, `didClose`.
4. **Реализация функций**: Запросы вроде `textDocument/documentSymbol` (для структуры файла) можно реализовать через парсинг синтаксического дерева. Более сложные функции, такие
   как `textDocument/definition` (переход к определению), потребуют полного семантического анализа и таблиц символов.

### 🚀 Интеграция с JetBrains IDE

Чтобы подключить ваш LSP-сервер к PyCharm или другой IDE JetBrains, нужно создать для него **плагин-клиент**. Это гораздо проще, чем писать полноценный языковой плагин.

1. **Требования**: Вам понадобится PyCharm с 2025.1 или новее. LSP API **доступно в бесплатном режиме** (код продукта `PY`). Оно недоступно в Community Edition.
2. **Создание плагина-клиента**: Плагин должен зарегистрировать ваш LSP-сервер для файлов с расширением `.miz`. Он запустит процесс сервера и будет передавать ему запросы от IDE.
3. **Дополнительные возможности**: В плагине можно также настроить базовый синтаксис (через **TextMate**-грамматики) для подсветки ключевых слов, пока сервер не запущен.

### 💡 Практические шаги для начала

1. **Изучите спецификацию LSP**. Это главный документ.
2. **Выберите библиотеку для LSP**. Для Python есть `python-lsp-server` или `pygls`, которые упростят реализацию протокола.
3. **Создайте минимальный сервер**, отвечающий на `initialize`. Подключите ваш парсер, чтобы реализовать `textDocument/documentSymbol` (вывод списка определений в файле).
4. **Протестируйте сервер** через расширение LSP в VS Code, чтобы быстро отладить логику.
5. **Напишите простой плагин для JetBrains**, который запускает ваш сервер для файлов `.miz`.
