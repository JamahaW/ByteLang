# ByteLang

Экспериментальный системный язык программирования, в котором типы являются выражениями первого класса, а метапрограммирование интегрировано в ядро языка. ByteLang проектируется для низкоуровневых
вычислений с явным контролем над памятью и стековыми фреймами.

## Основные концепции

### Типы как выражения

В ByteLang не существует разделения между типами и выражениями. Указатели, массивы, структуры и сигнатуры функций — всё это выражения, которые могут вычисляться на этапе компиляции.

```rust
// Указатель — выражение
def u8_ptr = *u8

// Массив — выражение  
def buffer = [1024]u8

// Структура — выражение
def Point = struct {
    x: i32,
    y: i32
}
```

### Унифицированная система узлов AST

Абстрактное синтаксическое дерево ByteLang построено на принципе двойственной природы узлов: один узел может одновременно являться выражением, оператором и объявлением в зависимости от контекста
использования.

### Модульность через структуры

Модули в ByteLang реализованы как структуры. Импорт модуля создаёт символ, значением которого является тип структуры с публичными членами импортируемого модуля.

```rust
// Импорт модуля
def math = import("math.bl")

// Использование публичных членов
def result = math.add(5, 3)
```

### Явное управление исполнением

Язык предоставляет примитивы для явного управления стеком и вызовами функций, что позволяет точно контролировать низкоуровневые аспекты исполнения.

## Синтаксические конструкции

### Объявления символов

```rust
// Определение символа (константа, тип, функция)
def PI = 3.14
def String = []u8
```

### Объявление переменных

```rust
// Локальная переменная с инициализацией
var x: i32 = 10

// Глобальная неинициализированная переменная  
pub var buffer: [1024]u8 = undefined
```

### Структуры

```rust
// Определение структуры
def User = struct {
    // Публичное поле
    pub name: String,
    
    // Приватное поле
    age: i32,
    
    // Метод структуры
    def getAge = fn(self: *User) i32 {
        return self.age
    }
}
```

### Функции

```rust
// Определение функции
def add = fn(a: i32, b: i32) i32 {
    return a + b
}

// Функция, возвращающая тип (generic)
def Vector = fn(T: type) type {
    return struct { x: T, y: T }
}

// Использование generic-функции
def Vector2i = Vector(i32)
```

### Низкоуровневые операции

```rust
// Приведение к нативному указателю функции
def exit = cast(*(code: u32) void, 0x00)

// Загрузка внешних данных
def resource = load("data.bin")
```

## Архитектура компилятора

### Текущий статус

- **Лексический анализ**: Реализован лексер с поддержкой различных систем счисления и escape-последовательностей в строках.
- **Синтаксический анализ**: Завершена разработка рекурсивного нисходящего парсера. AST построено на принципе унификации типов и выражений.

### Дорожная карта разработки

#### Этап 1: Семантический анализ

- Проверка типов и разрешение символов
- Анализ областей видимости
- Верификация согласованности generic-параметров
- Проверка сигнатур функций и методов

#### Этап 2: Проектирование виртуальной машины

- Разработка формата байт-кода
- Проектирование системы управления памятью
- Реализация механизма стековых фреймов
- Создание интерфейса для нативных функций

#### Этап 3: Генерация кода

- Трансляция AST в байт-код
- Реализация базовых оптимизаций (инлайнинг, свёртка констант)
- Генерация метаданных для отладки
- Поддержка нескольких целевых архитектур

#### Этап 4: Верификация и тестирование

- Разработка тестового набора для базовых конструкций языка
- Создание эталонных реализаций алгоритмов
- Написание документации и примеров кода
- Интеграция с системами сборки

#### Этап 5: Расширение языка

## Философия дизайна

1. **Прозрачность исполнения**: Каждая конструкция языка должна иметь предсказуемое представление на уровне байт-кода.

2. **Минимализм синтаксиса**: Язык строится на небольшом наборе базовых конструкций, из которых композиционно строятся более сложные.

3. **Единообразие**: Принципы, применимые к одной части языка, должны работать и в других контекстах.

4. **Контроль над ресурсами**: Программист должен иметь возможность явно управлять распределением памяти и стековыми операциями.
